# Sentinel Implementation Plan

**Goal:** Build the approved first release with an enforced local redaction and review boundary.
**Architecture:** Extension-origin UI, content-script DOM adapter, privileged service worker, local encrypted vault, and a shared sanitizer/action policy. Provider input is an explicit sanitized object tied to a document revision.
**Tech Stack:** JavaScript ES modules, Chrome Manifest V3, Web Crypto/IndexedDB, Transformers.js, esbuild, Node test runner, Playwright.
**Spec:** ../specs/2026-09-09-sentinel-design.md

## Global constraints
- No inference before separate Approve and Run actions.
- No screenshot transmission; Gmail and OCR/vision are later phases.
- No secret values in model requests; resolve profile fields locally.
- Work in this new, otherwise empty project directory (no existing Git repository).
- Execute inline, test privacy boundaries before UI integration.

- [x] Write tests in tests/core.test.js for sanitizer, vault encryption, schema validation, routing, and approval invalidation.

## Test examples defining contracts
```js
assert.equal(redact('Hello jane@example.com', {}), 'Hello [EMAIL]');
assert.throws(() => validateAction({type:'navigate',url:'javascript:alert(1)'}, []));
const s = new Session();
s.review({revision:'one'});
assert.throws(() => s.take());
s.approve();
assert.equal(s.take().revision, 'one');
assert.throws(() => s.take());
```
